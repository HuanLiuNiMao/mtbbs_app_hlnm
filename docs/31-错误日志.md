# 错误日志
> 适用：想改错误采集范围、日志页形态、日志文件格式，或用户反馈“错误日志里没有我说的那条”时读。**非必读**。

## 一句话

崩溃与未捕获的异常会**自动**落到应用私有目录的一个 JSON Lines 文件里，用户在「关于 → 错误日志」里可看、可逐条复制、可清空。页面形态整页借鉴 PiliPlus。

## 出处与差异

形态、交互、信息卡的三节划分（设备 / 应用 / 编译）、卡片的「折叠 + 复制」都与 **bggRGjQaUbCoE/PiliPlus**（<https://github.com/bggRGjQaUbCoE/PiliPlus>）的 `lib/pages/setting/pages/logs.dart` 一致。页面顶部有常驻小字标注出处——这是**功能需求的一部分**，不要顺手删掉或移进滚动区。

两处刻意的差异：

| 点 | PiliPlus | 本仓库 | 为什么 |
|---|---|---|---|
| 采集 | `catcher_2`（自带 FlutterError / PlatformDispatcher / Isolate 三处钩子 + 文件 handler） | 自己装 `FlutterError.onError` 与 `PlatformDispatcher.onError` | 本仓库依赖版本锁得死（`docs/09`），加一个带原生依赖的崩溃库要连带升一串包 |
| 落盘 | 一个 JSON 数组文件（`.pili_logs.json`），清空靠 `truncate` | JSON Lines 追加写（`error_logs.json`） | 追加只需一行，不用“读全量 → 改数组 → 写回”；单行损坏只丢一条 |
| 入口 | 设置 → 日志 | **关于 → 数据管理 → 错误日志**，另在设置搜索登记一行 | 需求指定放关于页；搜索那条是为了让搜“错误日志”能找到 |

## 文件与容量

- 位置：`{appDataDir}/error_logs.json`（`AppPaths.appDataDir`）。**刻意不用** `getApplicationDocumentsDirectory`：Windows 上那是用户的“文档”目录，日志不该混进去。
- 格式：每行一个 JSON 对象，字段 `at` / `error` / `stack` / `source` / `context`；后两个可缺省。
- 上限：**200 条**（`ErrorLogStore.maxEntries`），超出从最旧丢；单条字段上限 2 万字符，超长截断并标 `…（已截断）`。
- 卸载即清；「清空日志」只清空文件内容，不删文件（删了下次写还得重建）。

## 采集范围（以及为什么抓不到某些错）

| 场景 | 是否会记 | 说明 |
|---|---|---|
| Widget 构建 / 布局 / 绘制抛异常 | 会 | `FlutterError.onError` |
| 未 `await` 的 Future 抛错、`Timer` 回调抛错 | 会 | `PlatformDispatcher.onError` |
| **`await` 里抛出的异常被业务 `try/catch` 吞掉** | **不会** | 被吞了就没有“未捕获”，这类要主动调 `ErrorLogStore.report` |
| **原生侧崩溃（Java / Kotlin / C / 渲染进程 SIGSEGV）** | **不会** | 进程直接没了，Dart 侧没机会执行；这类要看 logcat / 系统崩溃报告 |
| 启动早期（`install()` 之前） | 不会 | 所以 `install()` 放在 `main()` 第一行 |

排查用户反馈时先看这张表：**看不到日志 ≠ 日志功能坏了**，很可能是原生崩溃或被 catch 了。

## 踩过的坑

### 日志页字段名 `build` 与 `StatelessWidget.build()` 冲突

症状：`flutter analyze` 报 `conflicting_field_and_method` 与 `duplicate_definition`，编译不过。根因：给信息卡传参时用了 `build:` 这个形参名，而 `StatelessWidget` 本来就有 `Widget build(BuildContext)`。修法：形参/字段改为 `buildInfo`。教训：给 Widget 加参数时避开框架已有的成员名（`build` / `key` / `createState`）。

### `_copyAll` 与 `exportText` 各写一套格式

症状（修于本次）：页面「复制日志」用 `map(format).join` 拼，`exportText` 用分隔线拼，两处格式不一致，改一处忘另一处。修法：页面改为 `await ErrorLogStore.instance.exportText()` 再包代码块。教训：同一份“导出文本”只能有一个生产者。

### 单条写失败不能把主流程带下去

`ErrorLogStore.add` 内部 `try/catch` 且**不 rethrow**，写盘失败只 `AppLogger.w`。理由：日志是旁路能力，磁盘满 / 权限异常时不该让用户原本的操作也失败。

### 连续抛错时的行交错

同一帧内可能连续触发多条错误。若直接并发 `writeAsString(append)`，两行会互相插断（变成两行半截 JSON）。修法：`_writeQueue` 用 Future 链把写入**串行化**，且每次写完才裁一次。

## 怎么测

```bash
# 纯逻辑（序列化往返 / 容错解析 / 文本格式）
flutter test test/error_log_test.dart

# 端到端（需真机或桌面跑起来，debug 包才有「引发错误」菜单项）
flutter run
# → 关于 → 错误日志 → 右上角菜单 → 引发错误 → 下拉刷新
```

`test/error_log_test.dart` 只覆盖纯逻辑：文件读写要走 `path_provider`，widget 测试无插件实现。落盘那一层靠上面的手测路径覆盖。
