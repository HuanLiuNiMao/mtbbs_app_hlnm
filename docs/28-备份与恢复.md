# 备份与恢复（自定义备份项 / Web 备份 / 运行日志）

> 适用：新增或修改备份项、排查「导出的包缺了什么」「导入后某项没生效」、接入 Web 备份服务器时读。按需。

## 一句话

备份从「一刀切导出全部设置」改为**可勾选的模块化备份包**：`BackupCatalog` 声明有哪些项，`BackupCollectors` 提供读/写实现，`BackupService` 按勾选裁剪并逐项记日志。**未勾选的项不进包，导入时也不动本机对应数据**——这是整套设计的核心保证。

## 分层与职责

| 层 | 文件 | 职责 |
|---|---|---|
| 声明（唯一事实来源） | `lib/models/backup/backup_item.dart` | `BackupItemId` 枚举、`BackupCatalog` 项声明（标题/副标题/图标/默认勾选/父分组/包内键名/依赖/敏感）、`BackupSelection` 勾选运算 |
| 包格式 | `lib/services/backup/backup_pack.dart` | `mtbbs.backup` v2 编解码；旧版 `mtbbs.settings` / `mtbbs.cookies` 识别转换 |
| 读写实现 | `lib/services/backup/backup_collectors.dart` | 每个叶子项一个 `BackupItemHandler(key, collect, apply)` |
| 注册表 | `lib/services/backup/backup_registry.dart` | key → handler；`missing` 暴露「声明了但没实现」的项 |
| 编排 | `lib/services/backup/backup_service.dart` | 按勾选收集、逐项容错、可选事务回滚、写运行日志 |
| Web 上传 | `lib/services/backup/backup_web_client.dart` | 用户自备服务器的 POST/PUT 上传 |
| 运行日志 | `lib/services/backup/backup_log_entry.dart` + `backup_log_store.dart` | 结构化运行日志 + 环形落盘 |
| 设置持久化 | `lib/models/settings/backup_settings.dart`（`AppSettings.backup`） | 勾选项、Web 服务器配置、定时策略、日志保留天数、上次备份时间 |
| 系统级调度 | `lib/services/backup/backup_scheduler.dart` | WorkManager 周期任务注册 / 取消 / 后台执行入口（见「定时自动备份」） |

| 设置写操作 | `lib/providers/settings_provider_backup.dart`（`part of settings_provider.dart`） | 勾选/配置变更落库 + notify |

## 备份项清单（当前 11 个叶子）

应用设置、站点设置、快捷方式、MT 图床上传历史、**浏览记录·用户**、**浏览记录·帖子**（两者归在 `browseHistory` 分组下，可整组勾选或单独勾选）、编辑框设置、编辑框草稿（依赖编辑框设置）、内容过滤、MCP 配置（敏感）、账号与 Cookie（敏感，依赖站点设置）。

勾选默认值：`defaultSelected: true` 的项在首次运行/重置时勾上；草稿、MCP、Cookie 默认不勾。

## 关键设计决策

- **枚举名冻结**：`BackupItemId` 的枚举名会写进 `AppSettings.backup.selected`，改名等价于用户丢勾选状态（回落默认值）。包内键名另由 `payloadKey` 定义，与枚举名解耦，所以「UI 名字」与「包内键名」可各自演进。
- **分组父不产生 payload**：`payloadKey == null` 即分组头，只用于 UI 聚合（全选/半选由子项推导）；写进包里的永远是叶子项。
- **依赖用 `requires` 表达，取消要级联**：勾草稿自动勾编辑框设置；取消编辑框设置会级联取消草稿（`BackupSelection.toggled` 里做）。漏了级联会出现「包里只有草稿、没编辑器设置」的半残状态。
- **导入有固定顺序**（`BackupCatalog.applyOrder`）：站点设置必须早于快捷方式与 Cookie（前者决定 host 是否存在、后者要 host 的 baseUrl）。顺序错的表现是「导入后快捷方式被清空」。
- **两份数据永不被包覆盖**：应用设置导入时强制保留本机 `currentSiteHost`（包里的站点在本机可能不存在，会导致启动落在空站点）与 `backup`（勾选状态本身，否则用户下次备份选项莫名变化）。
- **事务式导入靠「同一套 collector 拍快照」**：`BackupImportStrategy.atomic` 下失败按快照 `replace` 写回；快照本身失败的模块会在日志里标「不可回滚」，此时数据可能处于中间态——回滚失败会显式记 `e` 级日志。
- **Web 备份 = 用户自备服务器**：本应用不提供托管服务，也不内置任何默认地址。约定请求体就是备份包 JSON（`Content-Type: application/json`），**2xx 即成功、不解析响应体**，从而兼容任意自建实现（NAS 脚本、WebDAV 网关、Serverless 函数）。
- **仅 Wi-Fi 用网卡名启发式**：项目未引入 `connectivity_plus`（不为单一开关加依赖），命中 `wlan*`/`wifi*`/`wi-fi*` 视为 Wi-Fi；**探测失败时放行**（宁可上传成功，也不因探测失败静默跳过备份）。

## 新增一个备份项（最小步骤）

1. `BackupItemId` 加枚举值（**发布后不可改名**）。
2. `BackupCatalog.all` 加 `BackupItemSpec`：`title/subtitle/icon/defaultSelected/payloadKey`；分组用 `payloadKey: null` + 子项 `parent:`；含凭据用 `sensitive: true`；有先后依赖用 `requires:`。
3. `backup_collectors.dart` 加 `BackupItemHandler(key: <同 payloadKey>, collect:, apply:)`。
4. 若该项被别的项依赖（或依赖别人），在 `BackupCatalog.applyOrder` 里插入正确位置（不插则排最后）。

完成 1~2 后**自动生效**：UI 复选框（含分组/半选/依赖级联）、包内键名与裁剪、运行日志条目、`BackupRegistry.missing` 校验。缺 handler 的项**不会静默丢数据**：收集时记 `w` 日志「备份项 $key 无实现，跳过」，并在运行日志中标记该项失败。

## 日志规范（TAG = `BACKUP`）

两套日志别混用：

- **调试日志** `AppLogger`（`lib/core/utils/logger.dart`）：release 下静默，TAG 统一 `'BACKUP'`（工具会右对齐到 12 宽，别自造第二 TAG）。`i` = 里程碑（收集完成/上传结果/日志落盘）；`w` = 可恢复异常（回退内存值、未知模块、跳过、探测失败、持久化失败）；`e` = 数据风险（收集/还原失败、回滚失败，带 `StackTrace`）。
- **用户可见运行日志** `BackupLogStore`：落 `app_settings` KV 的独立键 `backup_run_log`（不塞进 `settings_app` 文档，因为日志会持续增长）。每次导出/还原一条 `BackupRunLogEntry`：`id`（时间戳 base36）、`at`、`phase`(export/import)、`trigger`(manual/web/scheduled/legacy)、`keys`、逐项 `BackupItemLog`（`count`/`durationMs`/`error`）、`detail`。环形保留 `maxEntries = 50` 条 + `keepDays` 天（默认 30，0 = 不保留），可导出纯文本 / JSON。
- **禁止**打印鉴权头值、Cookie 明文、令牌。Web 上传日志一律经 `BackupWebClient.redactUrl`（丢掉 query 与 fragment，只留 `scheme://host/path`），令牌放 query 里也不会外泄。

## 定时自动备份（`BackupScheduler` + WorkManager）

`lib/services/backup/backup_scheduler.dart`，单例。由两处驱动：`main.dart` 启动时 `init()` 一次，`SettingsProvider` 在设置变更 / 导入设置后调 `sync()`。

- **用 WorkManager 而不是 `Timer.periodic`**：用户要的是「一周备份一次」。Timer 只在 App 进程存活时走，手机重启或清理后台之后就不再执行，等于没做。WorkManager 把周期任务注册进系统 JobScheduler，**App 不在前台、进程被杀也会被系统唤起**。
- **周期按「数值 + 单位」存**（`BackupSchedulePolicy.interval/unit`，单位支持分钟/小时/天/周）：让用户自己算 10080 分钟既反人类也容易算错；系统侧统一换算成分钟。
- **15 分钟钳制**：Android 周期任务硬下限是 15 分钟，低于它系统会自动抬到 15。`_effectiveMinutes` 主动做同样的钳制，保证「日志里写的周期」=「系统实际周期」。
- **`sync()` 幂等**：靠 `_registeredMinutes` 与 `_registeredConstraints` 两个指纹比对——周期和约束都没变就直接返回，不重排；变了才 `registerPeriodicTask(existingWorkPolicy: update)`。用 `update` 而非已弃用的 `replace`，能原地改参数而不掐掉正在跑的那次。
- **三个约束条件映射到 WorkManager `Constraints`**：仅 Wi-Fi → `NetworkType.unmetered`（否则 `connected`）、需充电 → `requiresCharging`、电量不低 → `requiresBatteryNotLow`。
- **后台 isolate 必须自己读盘**：每次触发原生侧会新建独立 `FlutterEngine`（见插件 `BackgroundWorker.kt`），主 isolate 的内存状态全部不在。因此 `runScheduledBackup()` 依次做：读 `app_sites` KV 解析成 `List<Site>` → `SettingsRepository.loadAll(hosts)` → `SiteStore.instance.replaceSites(sites)`（**不填则「按站点遍历」的项全是 0 条**）→ 导出 → 上传。
- **结果只能落库，不能回调**：跨 isolate 拿不到主 isolate 的闭包，所以 `_writeBackRunResult` 直接 `SettingsRepository.setApp(...)` 写 `web.lastRunAt/lastResult` 与 `web.schedule.lastRunAt/lastResult`（两处同源写入，避免「页面显示上次时间、实际判断用另一个字段」），主 isolate 下次 `load()` 才看到。
- **失败不重试风暴**：所有「不该跑」的分支（Web 未启用 / 地址无效 / 未开定时 / 未勾任何项）以及异常分支一律 `return true`，把失败交给应用层日志与 UI——用户服务器挂掉时，系统级无限重试只会更糟。退避策略仍配了 `exponential` + 15 分钟起，用于「系统提前终止」这类场景的补偿。
- **能力门控**：`AppCapability.backgroundTask`。`initialize` 抛异常（鸿蒙无实现、插件未注册）即 `disable` 该能力位，UI 隐藏定时入口，手动上传不受影响。
- `runNow(web)` 留作调试：注册一次性任务验证链路，不受周期限制。

## 凭据存储（`SecretStore`）

- `SecretStoreMode{plain, secure}`，UI 里让用户自己选：**明文**（随 `settings_app` 文档，简单、可导出）或 **密钥库**（`flutter_secure_storage`，Android 走 `encryptedSharedPreferences: true`）。
- `lib/platform/optional/secure_store.dart` 是**唯一** import `flutter_secure_storage` 的地方，属「可选平台能力」层；`MissingPluginException` / `PlatformException` 一律降级并记 `w` 日志，同时 `AppCapabilities.disable(secureStore)`。
- 键前缀 `mtbbs.backup.secret.`，Web 备份鉴权值键名 `web_backup_auth`（`BackupWebClient.secretKey`）。
- `WebBackupConfig.toMap()` 在 secure 模式把 `headerValue` 写成空串——避免「以为加密了，其实文档里还留了一份明文」。
- `setWebBackupSecretMode` 双向搬值：转 secure 时写密钥库并清空明文字段；转 plain 时把密钥库值搬回文档并删除密钥库副本。转 secure 前先查 `SecretStore.available`，不可用则返回 false 且不改设置。
