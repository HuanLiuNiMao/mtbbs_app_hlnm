# 内容过滤（板块名单 / 帖子与评论屏蔽）

> 适用：新增/修改「屏蔽」类能力、调整评论屏蔽的触发方式、排查「屏蔽没生效 / 误伤正常回复」。实现集中在 `lib/core/utils/content_filter.dart`，本文件只讲取舍与坑。

## 两套屏蔽，各自独立

| 能力 | 作用对象 | 配置形态 | 设置入口 |
|---|---|---|---|
| 帖子列表屏蔽 | 列表里的主题卡片（`ThreadItem`） | 每个列表点一份 `ThreadScopeFilter` | 「帖子列表屏蔽」二级页 |
| 评论屏蔽 | 楼层正文（`PostItem` / 裸 bbcode） | 全局一份 `CommentFilterConfig` | 「评论屏蔽」二级页 |

四个列表点是 `community` / `guide` / `search` / `user`（社区、导读、搜索、个人主页）。两者共用同一套**关键词匹配语义**（`CommentWordMatcher`：合法正则按正则、非法正则退化为子串、大小写不敏感）与同一个**板块名单语义**（`filterByBoard`：黑名单命中即隐藏、白名单未命中即隐藏）。

## 评论屏蔽的触发方式

`CommentFilterConfig` 有开关、两种触发方式、屏蔽词，**没有内置默认词表**（屏蔽词完全由用户维护，为空即不屏蔽任何评论）。

| 触发方式 | 字段 | 生效条件 |
|---|---|---|
| 不设置（默认） | — | 屏蔽词对所有主题生效（`isGlobalTrigger`） |
| 仅隐藏贴 | `onlyHiddenThread` | 当前主题是隐藏贴 |
| 分板块 | `boards` + `modeBlock` | 当前主题板块命中 `filterByBoard` |

两者是**或**关系：任一命中即应用屏蔽词。判定入口统一是 `commentFilterApplies(f, boardName:, isHiddenThread:)`，`filterPostItems` 与 `shouldBlockCommentBbcode` 都只调它，不要在各调用点自己写 `if`。

「隐藏贴」的判据是 `isHiddenThreadBbcode`：`[appdata]{"type":"locked"}`（未回复时的 🔒 占位）或 `[hide]...[/hide]` 块。两者都是解析层已产出的标记，**不需要额外请求**。locked 正则只在 `content_filter.dart` 维护一份（`kLockedAppdataRe`），帖子页「回复后重取主帖」也用它。

「分板块」需要当前主题的板块名。详情页拿不到 `ThreadItem.boardName`（那是列表页字段），所以 `ThreadViewData` 单独补了 `boardName`，由详情解析从面包屑（`parseBoardFields`）提取；解析不到时为空串，此时该触发条件视为**无法命中**（保守不屏蔽）。

## 三个消费点

| 位置 | 入口 | 上下文 |
|---|---|---|
| 帖子详情评论区 | `filterPostItems` | 有 `boardName` + `isHiddenThread` |
| 「我的帖子」展开回复 | `filterPostItems` | 同上（取自同一次详情结果） |
| 消息 → 我的帖子（回帖预览） | `shouldBlockCommentBbcode` | 只有单条 bbcode，**拿不到上下文** |

消息页只隐藏回帖正文并给一行「回帖内容已屏蔽」提示，保留「查看 / 回复」入口——用户点进去仍能按完整上下文看到原帖。

消息页拿不到板块与隐藏贴标记，所以**不参与**触发方式判定（调 `withoutTrigger()`）：只要开关开着且有屏蔽词就过滤。若沿用触发方式，会被判为「无法命中」而永久不过滤，与「消息里也过滤」的需求相悖。触发方式是为浏览帖子时的评论区做精细控制用的。

## 必须保留的不变量

- **判定链顺序**：去空白为空 → 不屏蔽；超过 10 字 → 不屏蔽；纯 ASCII 可打印且不含 `.` → 屏蔽；命中屏蔽词 → 屏蔽。这条链是用户已习惯的屏蔽强度，改它等于悄悄改变行为。
- **两条豁免**：楼主帖（`isOp`）与「回复别人」的楼层（带非提示类引用块）不屏蔽。引用块里是「回复可见」提示时不算回复别人，仍按正常规则判定。
- **「我的帖子」先去重再过滤**：`authorid` 筛选下 `isOp` 全为 false，首条是楼主帖、靠 uid 对比去重；若先过滤再 `sublist(1)`，首条被屏蔽后会把真实回复误删。顺序写在该文件注释里，不要调换。
- **补页判据**：过滤后可见条数不足一页基准时自动向后扩窗，判据用 `commentFilterApplies` 而不是裸开关——触发方式不命中的主题不该触发补页。

## 迁移与备份

评论屏蔽从「`commentFilterKeywords` + `commentBlockEnabled`」两个扁平键升级为一份 JSON（key = `commentFilter`）。首次加载时若 `commentFilter` 不存在，读旧键做一次性迁移：**剔除以 `康康看下|` 开头的旧内置词行**（那是被删除的内置词表合并成的正则，不剔除会表现为「内置词没删掉」），保留用户自加的词，然后把三个旧键（含 `commentBlockWordsVersion`）删掉。

备份键清单（`lib/services/backup/backup_collectors.dart`）只列 `commentFilter`，不再列旧键——否则恢复旧备份会把废弃键写回来，与迁移逻辑打架。

## 踩坑记录

**症状**：升级后内置屏蔽词仍在生效，用户删了也没用。
**根因**：旧版把 80 条内置词合并成一条 `|` 正则写进用户设置，那条数据属于用户设置而不属于代码常量，删常量不影响已升级的用户。
**修法**：迁移时按 `康康看下|` 前缀剔除该行（见 `settings_provider_persistence.dart`）。
**教训**：预置进用户数据的默认值，删除时必须同时写迁移；只删代码常量等于没删。
