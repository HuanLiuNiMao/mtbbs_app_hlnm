# 跨站点会话与多用户

> 适用：把新页面改造成"能以别的站点身份打开"、排查跨站链接落到浏览器、调整默认用户逻辑时读。按需。

## 问题

`ApiService` 单例把 baseUrl + CookieJar 绑死在"全局当前站点 + 当前账号"，于是别的站点链接
只能 toast「请切换站点」。C 端真实的用法是：在 A 站看到 B 站的帖子链接，想直接读。

## 设计一句话

**全局仍只有"当前站点 + 当前账号"，但身份与 Dio 变成可按页面传入的参数**：
页面从 `SiteScope` 取当前上下文的 `SiteSession`，不再直接读 `ApiService().dio` /
`SiteStore.instance`。没传 `site` 参数时 `SiteScope` 不存在，页面拿到的 `GlobalSiteSession`
等价于旧行为 —— 所以迁移可以一页一页做，不影响未迁移页面。

| 层 | 文件 | 职责 |
|---|---|---|
| 会话 | `lib/core/app/site_session.dart` | `GlobalSiteSession`（跟随全局）/ `FixedSiteSession`（固定站点 + 账号，`temporary=true`） |
| 注册表 | `lib/core/app/session_registry.dart` | 预加载各站账号与默认账号、按 location 解析会话、建/丢作用域 Dio |
| 作用域 | `lib/core/app/site_scope.dart` | `InheritedWidget`；`withSiteParam` / `withoutSiteParam` |
| 无状态 Dio | `lib/services/api_service.dart` | `_createDio(baseUrl, jar)` + `scopedDio(host, account)` 缓存 |

## URL 约定
- `site=<host>`：本页临时以该站点身份访问（缺省用该站**默认用户**，未设置为游客）
- `as=<账号>`：显式覆盖默认用户（仅调试/特殊入口用，界面不主动生成）
- `anon=1`：本页以**当前站点的游客身份**访问（不带任何登录 cookie，只读）
- `site` 等于当前站点 → 视作无参数（`sessionForLocation` 直接返回 null），避免"跨站身份读本站"

链接 → 页面的**唯一决策点**是 `UrlRouter.resolveTarget`：能映射到 App 页面且属于当前站点 →
直接路径；属于已配置站点且页面已迁移 → 追加 `site=`；其余 → `/browser?...&intercept=false`。
所有入口（首页链接、帖子正文链接、系统「打开方式」、搜索框、内置浏览器「用 App 打开」）
都必须走它，禁止各处再写一份判断（历史上就漏过兜底参数）。

## 为什么这么切

- **作用域 Dio 独立、磁盘目录共享**：每个上下文一个 `PersistCookieJar`
  实例（`cookies/{host}/{account}/`），避免两个 Dio 并发写同一个罐；磁盘路径相同，
  所以"跨站看到的就是该账号真实登录态"，不存在两套登录态。
  `PersistCookieJar` 不要跨 Dio 复用，也不要指望它做了跨实例同步。
  **当前站点不建作用域会话**：它本来就用全局 Dio，再建一份等于让两个
  `PersistCookieJar` 指向同一目录、互相覆盖（`refreshHost` 里直接 return）。
- **启动时预加载**（`SessionRegistry.init`）：路由 builder 是**同步**的，默认账号又是
  异步磁盘读取，只能提前算好放进内存。站点增删/域名变更后由
  `SettingsProvider._persistSites` 触发 `reloadAll()`（只比 host+baseUrl 签名，
  改板块排序不重建）；**切换当前站点**后由 `AppOrchestrator.switchSite` 触发：
  新当前站点必须丢掉旧的作用域会话，否则它的罐目录与全局活跃罐相同（见上一条）。
- **只读**：`SiteSession.canWrite => isLoggedIn && !temporary`。跨站默认账号只是"用来读"，
  写入仍要求主动切站点，否则会出现"以为在 A 站发帖、实际发到 B 站"。
- **身份解耦**：`SessionRegistryIdentity.bind(AuthProvider)` 由 `main` 注入，
  core 层不反向依赖 auth 层；注册表读账号直接走 `DatabaseHelper.getAccountsRaw`。

## 匿名访问（当前站点的游客身份）
入口：「我的」→「匿名访问用户主页」（弹 `UidPickerDialog` 输入 UID）→ `/user/:uid?anon=1`。
**语义**：用**当前站点的游客身份**打开目标用户主页 —— 请求完全不带登录 cookie，
站点侧只看到游客，不会在对方空间页的「最近访客」/在线列表里留下当前账号的足迹。
它和跨站点访问是两件事：跨站是「换站点、用该站默认账号读」（`site=` + `FixedSiteSession`
但 `anonymous=false`），匿名是「不换站点、不带身份读」（`anon=1` + `FixedSiteSession.anonymous=true`）。
所以参数不复用 `site=`，避免「当前站点」被 `sessionForLocation` 当作无参数而退化回登录身份。
- **独立 Cookie 罐**：`AppPaths.anonCookiesDirForHost(host)` → `{appDataDir}/anon_cookies/{host}`。
  刻意不放在 `cookies/{host}/` 根（会与全局游客罐两个实例指向同一目录互相覆盖），
  也不放在 `cookies/{host}/.anon/`（会被 `accountJarDirsForHost` 当成账号罐，
  `mirrorToAllJarsForHost` 会拿另一个实例往同一目录写）。同一个 host 的匿名会话在
  `SessionRegistry.refreshHost` 里**提前**创建（当前站点也要有，所以放在
  `if (host == SiteStore.instance.host) return;` 之前），建失败只记 `AppLogger.w` 不拖垮站点初始化。
- **只读**：`anonymous` 会话不写、不登录、不关注。`UserProfilePage` 的只读文案按
  `_session.anonymous` 分流（「匿名浏览为只读…」/「跨站点浏览为只读…」），
  关注态判据也从 `AuthProvider` 改成会话身份（匿名页不能用匿名 Dio 去问「我关注他没」）。
  页面顶部显示横幅「正在以游客身份匿名浏览（只读，站点不记录你的访问）」，右侧按钮
  `replace('/user/:uid')` 回到登录身份（`withSiteParam`/`pathFor` 之外的显式去参数）。
  匿名页也**不写本地浏览记录**（`_load` 里 `!_session.temporary` 才记）：否则历史里会留一条
  `routePath=/user/:uid` 的入口，点开就是登录身份，等于把"匿名看的"变成一次实名回访。
- **人机验证**：游客访问 Discuz 空间页常见 WAF 脚本挑战（实测返回 200 + 2.7KB
  `<script>var arg1='…'`），所以匿名页必须保留验证入口。`VerificationGate.verifyManually`
  带 `session:`，`_contextForUrl(url, pageSession:)` 在 `temporary` 时按 `anonymous` 选
  `anonJar(host)` 或 `scopedJar(host, account)`，回流与探测都写进匿名罐；
  否则匿名页的 host 与当前站点相同，会被误判成全局会话、验证结果写进登录罐，
  表现为「验证过了还是被拦」。
- **未配置站点**：`anonymousSessionForHost` 返回 null，调用方退回全局会话（页面能开，
  但那是登录身份），不白屏也不静默越权。
- 站内跳转：`SiteScope.pathFor` 优先看 `session.anonymous` → `withAnonParam`；
  复制/分享链接用 `withoutSiteParam` 时会同时去掉 `anon`，不把游客标记带出去。
- **与「页面接管」的关系**：入口先跑一次 `appPageRedirect(withAnonParam(...))`；
  若用户关掉了「用户主页」或开了站点级降级，路由会把它送去**内置浏览器** ——
  浏览器用登录态，等于"匿名入口"变成实名访问。所以命中时直接 toast 提示、不跳转，
  而不是让用户以为匿名了其实没有。

## 默认用户
持久化在站点设置的 `SiteSettings.identity.defaultAccount`（`settings_site` Store，key = host），游客 = 置空。
设置入口是「设置 → 账号设置 → 用户设置」(`/settings/users`；站点设置 →「默认用户」也跳这里），**以账号为键**：列出各站点
已登录账号，点进账号在详情页 (`/settings/user?host=&username=`) 打开
「该站点默认用户」开关；后续账号级行为（自动签到等）继续加在详情页。
改动后 `refreshHost` 重建该站全部作用域会话。

它刻意**不**放进「用户管理」弹窗：弹窗只负责当前站点的账号切换/导入导出/退出，
而"按账号的行为配置"放独立页面，避免弹窗变成设置中心。

## 头像与图片

- `UserAvatar` 的作用域判定在 `SiteScope.read(context)`：头像 URL 用**会话站点**
  的 `baseUrl` + 该站 `avatarTemplate`，否则跨站帖子里的头像会拿去当前站点的
  头像接口请求（自然取不到）。CDN 是全局设置，跨站不套用。
- 图片防盗链 Referer 按图片 URL host 反查站点（`refererForUrl`）。
- 处在跨站页面时，页面内跳转（头像 → 用户主页、用户主页 → 下一个用户）
  必须用 `SiteScope.pathFor(context, path)` 续接 `site=`，否则会退回全局身份。

## 新增页面接入（checklist）

1. 页面持有 `SiteSession _session`，在 `didChangeDependencies` 里
   `_session = SiteScope.of(context)` 并**首次**绑定后触发加载
   （不要在 `initState` 里 `dependOn`，也不要在 `initState` 直接发请求）
2. 所有请求用 `_session.dio`，拼接 URL 用 `_session.baseUrl`，
   本地缓存 / 历史记录的 host、viewer(uid) 用 `_session.host` / `_session.uid`
3. 写操作入口前加只读守卫（toast「跨站点浏览为只读…」），列表/卡片传
   `readOnly: _isCacheMode || _session.temporary`
4. 页面确实支持跨站后，把标识加进 `UrlRouter.crossSitePages`
   （当前：`thread` / `user` / `online` / `ranklist` / `darkroom` / `search`）；未加入的跨站链接继续走内置浏览器
5. 页面内的站内跳转一律走 `SiteScope.pathFor(context, path)`（或 `UrlRouter.resolveTarget`），
   不要直接 `context.push('/xxx')` —— 否则会丢掉 `site=`，把跨站页变回全局身份

## 已迁移页面（只读）

| 页面 | 路径 | 说明 |
|---|---|---|
| 帖子详情 | `/thread/:tid` | 隐藏回复栏/编辑器；收藏、评分、点赞、编辑均提示"先切站点" |
| 用户主页 | `/user/:uid` | 隐藏留言板/私信，好友/关注/积分记录等入口提示切站点 |
| 在线用户 | `/online` | 纯只读列表 |
| 用户排行 | `/ranklist` | 纯只读列表 |
| 小黑屋 | `/darkroom` | 纯只读列表 |
| 搜索结果 | `/search/result?kw=` | 纯只读列表；跨站入口来自 `search.php?srchtxt=` 链接 |

跨站页面统一语义：`SiteSession.temporary = true`，`canWrite` 恒为 false。
匿名访问（`anon=1`）复用同一套只读路径，区别只有两点：`anonymous = true`、
Dio/罐来自 `anon_cookies/{host}/`；目前只开放用户主页一个入口。
未迁移的页面（板块、导读、圈子、留言板、私信、积分记录等）仍走浏览器或提示切站点，
新增迁移时按上面的 checklist 做，别只改 `crossSitePages` 不搬 Dio。

列表组件（`ThreadGrid` / `ThreadCard`）的站内跳转已走 `SiteScope.pathFor`：
把帖子列表放进跨站页时，点标题/作者/头像会自动带上 `site=`；板块标签页尚未迁移，
跨站时给出"先切站点"提示而不是用全局身份打开。

## 已知限制

- 跨站页面**可以**弹人工验证：`InterstitialContext` 带上本次请求的
  `client / jar / baseUrl`，WebView 回流与探测都落在该站点自己的作用域罐
  （见 docs/07 #105）。跨站验证拿到的客户端级 cookie **不补写到该站点其它罐**
  （作用域罐是长生命周期实例，另写一份会互相覆盖），换账号后可能要再验证一次
- 跨站图片按 URL host 反查 Referer（`refererForUrl`），但附件下载不带作用域
  Cookie —— 需要登录态的附件在跨站页拿不到
- 板块、导读、圈子、搜索结果等尚未迁移，仍走内置浏览器兜底
